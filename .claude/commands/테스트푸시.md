`/테스트푸시` 를 실행하는 것 자체가 commit/push 에 대한 명시적 승인이다. 아래 순서로 한 번에 진행한다. (`test-push` 스킬과 동일한 흐름)

1. `mvn test` 실행. **하나라도 실패하거나 빌드 오류가 나면 여기서 중단**하고 실패 내용만 보고한다 (commit/push 하지 않음).
2. 전부 통과하면 `git status` / `git diff` 로 변경 내용을 확인한다. 변경이 없으면 "커밋할 변경 없음"으로 끝낸다.
3. 변경된 파일을 이름으로 지정해 stage 한다 (`git add -A` 금지, `target/`·`.idea/` 등 산출물·비밀값 제외). 이번 변경과 무관해 보이는 파일(스크린샷 등)이 이미 staged 상태라면 커밋에 포함하지 말고 보고한다.
4. 커밋 메시지는 기존 히스토리처럼 **한국어 한 줄 요약**으로 변경 내용을 설명하고, 시스템에서 지정한 Co-Authored-By 줄을 끝에 붙인다.
5. 현재 브랜치를 `git push` 한다. force push, `--no-verify` 는 사용하지 않는다. `main` 에서 실행한 경우에도 사용자가 요청한 것이므로 그대로 push 한다.
6. 결과(테스트 통과 수, 커밋 해시, push 대상 브랜치)를 짧게 보고한다.

참고: `mvnw` 는 저장소에 없으므로 시스템 `mvn` 을 사용한다. 기존 테스트는 Mockito 단위 테스트라 MySQL/Redis 없이 돈다.
